## 1. Общее описание

В работе реализована модель компьютера с собственным языком программирования, транслятором и симулятором процессора.

Основной путь выполнения программы:

```text
source.lisp
    ↓
lisp_parser.py
    ↓
Python-представление программы: list / int / str
    ↓
translator.py
    ↓
program.bin + program.data.json + program.disasm + program.vars
    ↓
machine.py
    ↓
выполнение программы по микрокоду
```

Архитектура процессора:

- стековая архитектура;
- гарвардская организация памяти: память команд и память данных разделены;
- микропрограммное управление;
- port-mapped ввод-вывод;
- поддержка аппаратных и программных прерываний;
- строковые литералы представлены в памяти данных в формате `pstr` — Pascal string.

## 2. Язык программирования

### 2.1. Общая идея

Язык является Lisp-подобным. Программа состоит из последовательности S-выражений.

Пример программы:

```lisp
(setq x 10)
(print-int (+ x 5))
(print-char 10)
```

После разбора парсер превращает исходный код в обычные Python-структуры.

Например:

```lisp
(+ 1 (* 2 3))
```

превращается в:

```python
["+", 1, ["*", 2, 3]]
```

---

### 2.2. Синтаксис

```bnf
program          ::= expression*

expression       ::= atom
                   | "(" list_expr ")"

atom             ::= integer
                   | symbol
                   | string_literal

integer          ::= ["-"] digit+
symbol           ::= (letter | special_char) (letter | digit | special_char)*
string_literal   ::= '"' char* '"'

list_expr        ::= form_setq
                   | form_if
                   | form_loop
                   | form_begin
                   | form_proc
                   | form_call
                   | form_interrupt
                   | form_arithmetic
                   | form_comparison
                   | form_io
                   | form_memory
                   | form_pstr

form_setq        ::= "setq" symbol expression
form_if          ::= "if" expression expression expression
form_loop        ::= "loop" expression expression*
form_begin       ::= "begin" expression*
form_proc        ::= "proc" symbol expression*
form_call        ::= "call" symbol

form_interrupt   ::= "interrupt" expression*
                   | "enable-interrupts"
                   | "disable-interrupts"
                   | "int" integer?

form_arithmetic  ::= ("+" | "-" | "*" | "/" | "%") expression expression+
form_comparison  ::= ("=" | "!=" | "<" | ">" | "<=" | ">=") expression expression

form_io          ::= "print" expression
                   | "print-pstr" expression
                   | "print-int" expression
                   | "print-char" expression
                   | "read-int"
                   | "read-char"

form_memory      ::= "load-at" expression
                   | "store-at" expression expression

form_pstr        ::= "pstr-len" expression
                   | "pstr-get" expression expression
                   | "pstr-set" expression expression expression

special_char     ::= "-" | "_" | "+" | "*" | "/" | "%" | "=" | "!" | "<" | ">" | "?"
digit            ::= "0".."9"
letter           ::= "a".."z" | "A".."Z"
```

Комментарии начинаются с `;` и продолжаются до конца строки.

Пример:

```lisp
; это комментарий
(setq x 1) ; это тоже комментарий
```

---

### 2.3. Литералы и escape-последовательности

Поддерживаются целые числа, символы и строковые литералы.

```lisp
42
-7
x
"Hello"
"Hello\n"
```

В строках поддерживаются escape-последовательности:

| Последовательность | Значение |
|---|---|
| `\n` | перевод строки |
| `\t` | табуляция |
| `\"` | кавычка |
| `\\` | обратный слэш |

Строки предполагаются ASCII-строками. Один символ хранится в одном машинном слове памяти данных, но при выводе через порт используется младший байт значения.

---

### 2.4. Семантика вычислений

Язык использует expression semantics: почти каждая конструкция оставляет результат на вершине стека.

| Конструкция | Результат |
|---|---|
| `integer` | само число |
| `string_literal` | адрес pstr-строки в памяти данных |
| `symbol` | значение переменной |
| `(setq x expr)` | значение `expr` |
| `(if cond then else)` | результат выбранной ветки |
| `(loop cond body...)` | `0` после завершения цикла |
| `(begin e1 e2 ... en)` | результат последнего выражения |
| `(proc name body...)` | не выполняется как обычный main-код, а размещается в памяти команд |
| `(call name)` | `0` после завершения процедуры |
| `(print expr)` | `0` |
| `(print-pstr expr)` | `0` |
| `(print-int expr)` | исходное значение `expr` |
| `(print-char expr)` | исходное значение `expr` |
| `(read-char)` | код прочитанного символа |
| `(read-int)` | прочитанное целое число |
| `(pstr-len s)` | длина pstr-строки |
| `(pstr-get s i)` | код символа по индексу `i` |
| `(pstr-set s i v)` | `0` |
| `(load-at addr)` | значение из памяти данных по адресу `addr` |
| `(store-at addr value)` | `0` |
| `(enable-interrupts)` | `0` |
| `(disable-interrupts)` | `0` |
| `(int)` / `(int 0)` | `0` после программного прерывания |

Обычные вычислительные формы вычисляют аргументы слева направо. Специальные формы имеют собственную семантику:

- `if` вычисляет условие и только одну из веток;
- `loop` вычисляет условие перед каждой итерацией;
- `begin` выполняет выражения последовательно;
- `proc` описывает процедуру, но не выполняет её при старте;
- `interrupt` описывает обработчик прерывания.

---

### 2.5. Типизация

Единственный машинный тип данных — 32-битное знаковое целое число.

Строки не являются отдельным машинным типом. Строковый литерал при трансляции размещается в памяти данных как `pstr`, а в выражении используется его адрес.

Логические значения:

```text
0        — ложь
не 0     — истина
```

Пример:

```lisp
(if (> x 0)
  (print "positive")
  (print "not positive"))
```

## 3. Строки: хранение и работа с pstr

### 3.1. Формат хранения строки

Строки хранятся в памяти данных в формате Pascal string.

Строка:

```lisp
"Hi"
```

размещается так:

```text
addr + 0 : 2       ; длина строки
addr + 1 : 72      ; 'H'
addr + 2 : 105     ; 'i'
```

Общий формат:

```text
addr + 0 : N               ; длина строки
addr + 1 : char_0
addr + 2 : char_1
...
addr + N : char_(N - 1)
```

Каждый символ занимает одно 32-битное слово памяти данных. При выводе символа в порт используется младший байт.

Максимальная длина строки — 255 символов.

---

### 3.2. Что возвращает строковый литерал

Когда в программе встречается строковый литерал:

```lisp
"Hello"
```

транслятор:

1. выделяет в памяти данных блок `N + 1` слов;
2. кладёт в первую ячейку длину строки;
3. кладёт дальше ASCII-коды символов;
4. в машинный код вставляет `PUSHI addr`, где `addr` — адрес начала pstr.

То есть выражение:

```lisp
(setq s "Hi")
```

компилируется по смыслу так:

```text
PUSHI <addr_of_Hi>
DUP
STORE <addr_of_s>
```

Переменная `s` хранит не саму строку, а адрес pstr-структуры.

---

### 3.3. Печать строки

Формы:

```lisp
(print "Hello")
(print-pstr "Hello")
```

эквивалентны по реализации. Обе ожидают, что выражение вернёт адрес pstr.

Пример:

```lisp
(setq s "Hello")
(print s)
```

Алгоритм печати строки:

```text
ptr = pstr_addr
len = memory[ptr]
ptr = ptr + 1

while len > 0:
    OUT memory[ptr]
    ptr = ptr + 1
    len = len - 1

push 0
```

В ISA нет отдельной инструкции `PRINT_STRING`. Транслятор вставляет inline-код печати строки: чтение длины, цикл, косвенное чтение через `LOADI`, вывод каждого символа через `OUT 1`.

---

### 3.4. Ограничения строк

- строки имеют фиксированную длину после размещения в памяти данных;
- нет динамического выделения памяти во время выполнения;
- строка — это адрес, поэтому `(print x)` корректно работает только если `x` содержит адрес pstr;
- для печати числа нужно использовать `print-int`, а для одного символа — `print-char`.

## 4. Память

### 4.1. Гарвардская архитектура

В модели используется гарвардская архитектура: память команд и память данных разделены.

Программист не может читать или менять память команд из программы. Данные читаются и записываются только через память данных и стек.

---

### 4.2. Память команд

Память команд содержит список инструкций ISA. Каждая инструкция занимает одно 32-битное слово.

Адресация выполняется по номеру инструкции:

```text
0 : JMP main_start
1 : код процедуры
...
k : код обработчика прерывания
...
n : основной код программы
...
m : HALT
```

В начало программы транслятор всегда вставляет `JMP main_start`. Это нужно, чтобы при запуске процессор сразу перешёл к основному коду и не начал выполнять тела процедур или обработчик прерывания как обычные инструкции.

---

### 4.3. Память данных

Память данных состоит из 32-битных знаковых слов.

Зарезервированные ячейки:

```text
0x00 : interrupt vector       ; адрес обработчика прерывания в памяти команд
0x01 : interrupt device cell  ; символ от внешнего устройства при IRQ
0x02 : первая свободная ячейка для пользовательских данных
```

Общая схема:

```text
Data Memory
+--------------------------------+
| 0x00 : interrupt vector        |
| 0x01 : interrupt device cell   |
| 0x02 : первая свободная ячейка |
| ...                            |
| s    : длина pstr              |
| s+1  : первый символ           |
| s+2  : второй символ           |
| ...                            |
| v    : переменная x            |
| v+1  : переменная y            |
| ...                            |
| tmp  : служебные переменные    |
+--------------------------------+
```

---

### 4.4. Переменные

Все переменные глобальные. При первом обращении к имени транслятор выделяет ему одну ячейку в памяти данных.

Пример:

```lisp
(setq x 1)
```

Если `x` получает адрес `2`, то генерируется примерно такой код:

```text
PUSHI 1
DUP
STORE 2
```

`DUP` нужен потому, что `setq` является выражением и должен оставить записанное значение на стеке.

Чтение переменной:

```lisp
x
```

компилируется как:

```text
LOAD <addr_of_x>
```

---

### 4.5. Служебные переменные транслятора

Некоторые операции языка разворачиваются в длинный inline-код. Для него транслятор выделяет служебные переменные в памяти данных.

Примеры:

```text
__pstr_ptr
__pstr_len
__read_int_ch
__read_int_value
__read_int_sign
__print_int_value
__print_int_digit_count
```

Они хранятся в той же памяти данных, что и пользовательские переменные.

## 5. Система команд ISA

### 5.1. Формат инструкции

Каждая инструкция кодируется в 32-битное машинное слово:

```text
31      24 23                    0
+----------+----------------------+
|  opcode  |       operand        |
|  8 bit   |       24 bit         |
+----------+----------------------+
```

- `opcode` — код операции;
- `operand` — операнд инструкции;
- для `PUSHI` операнд знаковый 24-битный;
- для адресных инструкций операнд беззнаковый;
- инструкции без операнда имеют `operand = 0`.

Диапазон для `PUSHI`:

```text
-8388608 .. 8388607
```

---

### 5.2. Набор инструкций

В таблице указаны фактические такты успешного выполнения инструкции с учётом `FETCH`.

| Инструкция | Hex | Операнд | Стековый эффект / смысл | Тактов |
|---|---:|---|---|---:|
| `HALT` | `0x00` | — | остановить процессор | 2 |
| `PUSHI` | `0x01` | `imm` | `-- value` | 4 |
| `DROP` | `0x02` | — | `a --` | 4 |
| `DUP` | `0x03` | — | `a -- a a` | 4 |
| `SWAP` | `0x04` | — | `a b -- b a` | 4 |
| `LOAD` | `0x10` | `addr` | `-- mem[addr]` | 4 |
| `STORE` | `0x11` | `addr` | `value --` | 4 |
| `LOADI` | `0x12` | — | `addr -- mem[addr]` | 4 |
| `STOREI` | `0x13` | — | `addr value --` | 4 |
| `ADD` | `0x20` | — | `b a -- b+a` | 7 |
| `SUB` | `0x21` | — | `b a -- b-a` | 7 |
| `MUL` | `0x22` | — | `b a -- b*a` | 7 |
| `DIV` | `0x23` | — | `b a -- b/a` | 7 |
| `MOD` | `0x24` | — | `b a -- b%a` | 7 |
| `EQ` | `0x30` | — | `b a -- int(b==a)` | 7 |
| `NE` | `0x31` | — | `b a -- int(b!=a)` | 7 |
| `LT` | `0x32` | — | `b a -- int(b<a)` | 7 |
| `GT` | `0x33` | — | `b a -- int(b>a)` | 7 |
| `LE` | `0x34` | — | `b a -- int(b<=a)` | 7 |
| `GE` | `0x35` | — | `b a -- int(b>=a)` | 7 |
| `JMP` | `0x40` | `addr` | `PC = addr` | 2 |
| `JZ` | `0x41` | `addr` | `cond --`, переход если `cond == 0` | 2 |
| `JNZ` | `0x42` | `addr` | `cond --`, переход если `cond != 0` | 2 |
| `CALL` | `0x50` | `addr` | сохранить `PC+1`, перейти | 2 |
| `RET` | `0x51` | — | вернуться по адресу из return stack | 2 |
| `IN` | `0x60` | `port` | `-- value` | 4 |
| `OUT` | `0x61` | `port` | `value --` | 4 |
| `INT` | `0x70` | `n` | программное прерывание | 2 |
| `IRET` | `0x71` | — | возврат из обработчика прерывания | 2 |
| `EI` | `0x72` | — | разрешить аппаратные прерывания | 2 |
| `DI` | `0x73` | — | запретить аппаратные прерывания | 2 |

---

### 5.3. Порты ввода-вывода

Ввод-вывод реализован через порты:

| Порт | Назначение |
|---:|---|
| `0` | входной поток |
| `1` | выходной поток |

`IN 0` читает один символ из входного потока и кладёт его код на стек.

`OUT 1` снимает значение со стека и добавляет младший байт в выходной поток.

Если входной поток закончился, машина останавливается с причиной:

```text
Input stream exhausted
```

Для программы [cat](./golden/cat.yml) это нормальное завершение:

Она бесконечно читает и печатает символы, пока не закончится входной файл.

## 6. Транслятор

### 6.1. Назначение

`translator.py` переводит Lisp-программу в машинный код для стекового процессора.

---

### 6.2. Этапы трансляции

```text
source.lisp
    ↓
tokenize(source)
    ↓
Parser.parse_program()
    ↓
list[Expression]
    ↓
Compiler.compile_program()
    ↓
list[Instruction]
    ↓
write_code()       → .bin
write_disasm()     → .disasm
json(data_memory)  → .data.json
variables          → .vars
```

---

### 6.3. Пример трансляции `setq`

Исходный код:

```lisp
(setq x 1)
```

После парсера:

```python
[["setq", "x", 1]]
```

После трансляции примерно:

```text
0: JMP 1
1: PUSHI 1
2: DUP
3: STORE 2
4: DROP
5: HALT
```

`DROP` добавляется после top-level выражения, потому что результат выражения больше не нужен.

---

### 6.4. Процедуры

Процедуры объявляются так:

```lisp
(proc hello
  (print "Hello"))

(call hello)
```

Процедуры:

- не имеют параметров;
- не имеют локальных переменных;
- используют глобальные переменные;
- выполняются ради побочных эффектов;
- после завершения возвращают `0`.

Тело процедуры размещается в памяти команд до основного кода. В конце процедуры транслятор добавляет:

```text
PUSHI 0
RET
```

Вызовы процедур используют `CALL addr`. Если процедура объявлена ниже места вызова, адрес патчится в конце трансляции через список `pending_calls`.

---

### 6.5. Условия

```lisp
(if condition then_expr else_expr)
```

Компилируется по схеме:

```text
compile condition
JZ else
compile then_expr
JMP end
else:
compile else_expr
end:
```

Условие считается ложным, если на стеке лежит `0`. Любое ненулевое значение считается истиной.

---

### 6.6. Цикл

```lisp
(loop condition
  body1
  body2
  ...)
```

Компилируется по схеме:

```text
loop_start:
    compile condition
    JZ loop_end
    compile body1
    DROP
    compile body2
    DROP
    ...
    JMP loop_start
loop_end:
    PUSHI 0
```

Цикл возвращает `0` после завершения.

### 7.4. DataPath

<p align="center">
  <img src="scheme/data path.jpg" alt="DataPath" width="850">
</p>

В модели используются следующие основные компоненты:

- `data_stack` — основной стек данных;
- `return_stack` — стек адресов возврата для `CALL` / `RET`;
- `data_memory` — память данных;
- `input_buffer` — входной поток, связанный с портом `0`;
- `output_buffer` — выходной поток, связанный с портом `1`;
- `reg_a` и `reg_b` — внутренние регистры операндов АЛУ;
- `alu_result` — регистр результата АЛУ;
- `zero_flag` и `negative_flag` — флаги результата АЛУ.

Процессор является стековым, поэтому почти все операции выполняются через `data_stack`. Верхушка стека — последний элемент списка `data_stack`.

#### Data mux

`data mux` выбирает источник значения, которое должно попасть на стек данных. Возможные источники:

```text
IR operand      -> для PUSHI
data memory     -> для LOAD / LOADI
input buffer    -> для IN
ALU result      -> для ADD / SUB / MUL / DIV / MOD / сравнений
```

Выбор источника задаётся сигналами из ControlUnit. На схеме это показано пунктирной стрелкой `select` от ControlUnit к `data mux`.

#### Работа с портами

Ввод-вывод реализован через port-mapped I/O.

| Порт | Назначение |
|---|---|
| `0` | ввод |
| `1` | вывод |

Инструкция:

```asm
IN 0
```

читает один символ из `input_buffer` и кладёт его ASCII-код на стек.

Инструкция:

```asm
OUT 1
```

снимает значение со стека и записывает младшие 8 бит в `output_buffer`.

#### Return stack

`return_stack` хранит адреса возврата из процедур. Он используется только ControlUnit при выполнении инструкций `CALL` и `RET`.

При `CALL addr`:

```text
return_stack.push(PC + 1)
PC = addr
```

При `RET`:

```text
PC = return_stack.pop()
```

Пользовательская программа напрямую не работает с `return_stack`.

#### АЛУ и флаги

АЛУ выполняет арифметические операции и сравнения:

```text
ADD, SUB, MUL, DIV, MOD
EQ, NE, LT, GT, LE, GE
```

Операнды берутся из регистров `A` и `B`, результат записывается в `alu_result`, после чего может быть помещён обратно на стек через микрооперацию `PUSH_ALU`.

Флаги:

- `zero_flag` устанавливается, если результат АЛУ равен `0`;
- `negative_flag` устанавливается, если результат АЛУ меньше `0`.

### 7.5. ControlUnit

<p align="center">
  <img src="scheme/control unit.jpg" alt="Control Unit" width="850">
</p>

ControlUnit содержит следующие основные элементы:

- `PC` — program counter, адрес текущей инструкции;
- `instruction memory` — память команд;
- `IR` — instruction register, регистр текущей инструкции;
- `opcode` — код операции из `IR`;
- `operand` — операнд из `IR`;
- `instruction decoder` — декодер инструкции;
- `microprogram memory` — память микропрограмм;
- `MPC` — microprogram counter, счётчик микроопераций;
- `control logic` — блок формирования управляющих сигналов;
- `branch logic` — логика переходов и изменения `PC`;
- `interrupt control` — блок обработки прерываний.

#### Общий цикл работы

Процессор работает по тактам. Один `FETCH` занимает один такт, и каждая микрооперация также занимает один такт.

Общий цикл работы ControlUnit:

```text
if IR is None:
    check interrupt
    if interrupt is pending:
        enter interrupt handler
    else:
        fetch instruction_memory[PC]
        load IR
        select microprogram by opcode
        MPC = 0
else:
    execute current_microprogram[MPC]
```


#### Instruction decoder и microprogram memory

`instruction decoder` получает `opcode` из `IR` и выбирает соответствующую микропрограмму из `microprogram memory`.

#### Microprogram Counter

`MPC` указывает, какая микрооперация текущей микропрограммы выполняется сейчас.

После большинства микроопераций `MPC` увеличивается на `1`.

Когда выполняется `END_INSTRUCTION`, ControlUnit очищает `IR`, сбрасывает `MPC` и на следующем такте снова переходит к `FETCH`.

#### Control logic

`control logic` получает текущую микрооперацию из `microprogram memory` и формирует управляющие сигналы для DataPath.

Например:

| Микрооперация | Что делает control logic |
|---|---|
| `PUSH_IR_OPERAND` | подаёт operand из `IR` через `data mux` на стек |
| `DROP` | удаляет вершину `data_stack` |
| `DUP` | дублирует вершину `data_stack` |
| `LOAD_DIRECT` | читает `data_memory[operand]` и кладёт значение на стек |
| `STORE_DIRECT` | снимает значение со стека и пишет в `data_memory[operand]` |
| `POP_A` | снимает вершину стека в регистр `A` |
| `POP_B` | снимает вершину стека в регистр `B` |
| `ALU_ADD` | запускает сложение `B + A` |
| `PUSH_ALU` | кладёт `alu_result` на стек |
| `PORT_IN` | читает символ из входного порта |
| `PORT_OUT` | выводит символ в выходной порт |

На схеме выход `signals` из ControlUnit идёт в DataPath. Эти сигналы управляют стеком, памятью данных, АЛУ, мультиплексорами и портами.

#### Branch logic

`branch logic` отвечает за изменение `PC`.

Обычные инструкции после выполнения увеличивают `PC` на `1` через микрооперацию `INC_PC`.

Инструкции перехода изменяют `PC` иначе:

| Инструкция | Действие |
|---|---|
| `JMP addr` | `PC = addr` |
| `JZ addr` | снять значение со стека; если оно равно `0`, то `PC = addr`, иначе `PC = PC + 1` |
| `JNZ addr` | снять значение со стека; если оно не равно `0`, то `PC = addr`, иначе `PC = PC + 1` |
| `CALL addr` | положить `PC + 1` в `return_stack`, затем `PC = addr` |
| `RET` | снять адрес из `return_stack` и записать его в `PC` |

На схеме `branch logic` получает `operand` из `IR`, потому что именно operand содержит адрес перехода для `JMP`, `JZ`, `JNZ` и `CALL`.

#### Interrupt control

`interrupt control` отвечает за аппаратные и программные прерывания.

Аппаратные прерывания проверяются только между инструкциями, то есть когда:

```text
IR = None
```

При наступлении аппаратного прерывания:

```text
1. interrupt control проверяет, что прерывания разрешены;
2. сохраняет контекст текущего выполнения;
3. записывает символ устройства в data_memory[0x01];
4. читает адрес обработчика из data_memory[0x00];
5. записывает этот адрес в PC;
6. запрещает вложенные прерывания;
7. начинает выполнение обработчика.
```

Ячейки памяти данных:

| Адрес | Назначение |
|---|---|
| `0x00` | interrupt vector — адрес обработчика прерывания в памяти команд |
| `0x01` | interrupt device cell — символ, пришедший от внешнего устройства |

Сохраняемый контекст включает:

```text
PC
reg_a
reg_b
alu_result
zero_flag
negative_flag
data_stack
return_stack
interrupt_enable
```

После завершения обработчик выполняет инструкцию `IRET`. Она восстанавливает сохранённый контекст и возвращает процессор к прерванной программе.

### 5. [double_precision](./golden/double_precision.yml)

Программа демонстрирует сложение чисел, которые не помещаются в одно машинное слово.

Алгоритм операций такой:

- Число представляется двумя частями в базе `10000`:

  ```text
  value = hi * BASE + lo
  BASE = 10000
  ```

- Исходные значения:

  ```text
  a = 4294967296 = 429496 * 10000 + 7296
  b = 4294967296 = 429496 * 10000 + 7296
  ```

- Сначала складываются младшие части;

- Если `sum_lo >= BASE`, выполняется перенос;

- Затем складываются старшие части с учётом переноса;

- Получение итогового значения;

- При выводе сначала печатается `sum_hi`, затем `sum_lo`;

- Младшая часть должна занимать ровно 4 цифры, поэтому перед `sum_lo` при необходимости печатаются ведущие нули;

- Вывод программы.

### 6. [prob1](./golden/prob1.yml)

Нужно найти максимальный палиндром, который получается при произведении двух трёхзначных чисел.

Можно заметить, что любой шестизначный палиндром имеет вид:

```text
abccba
```

Тогда его можно представить так:

```text
abccba =
100000a + 10000b + 1000c +
100c + 10b + a
```

Сгруппируем слагаемые:

```text
= 100001a + 10010b + 1100c
```

Вынесем общий множитель `11`:

```text
= 11 * (9091a + 910b + 100c)
```

Следовательно, любой шестизначный палиндром делится на `11`.

Значит, в произведении двух трёхзначных чисел хотя бы один множитель должен делиться на `11`, что используется в программе для сокращения количества проверок.
